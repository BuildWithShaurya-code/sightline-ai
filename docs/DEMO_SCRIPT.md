# Two-minute demonstration

Use your actual account, a consented short positive clip and an empty-scene control. Rehearse on the final device. No fixed password or PIN belongs in this script. Keep private contact details and addresses out of the recording.

| Time | Action | Suggested narration |
| --- | --- | --- |
| 0:00–0:15 | Show Dashboard | “SightLine helps an operator find and review relevant moments in a surveillance clip.” |
| 0:15–0:30 | Open Security contacts & location; show only dummy demo data you entered | “The response details belong to this account. Saving them does not contact anyone.” |
| 0:30–0:55 | Upload the short consented clip and start analysis | “This runs the original three-class model. Progress comes from the worker; these are real predictions.” |
| 0:55–1:20 | Open evidence, show time/confidence and confirm the candidate | “A detection is not proof of theft. The operator reviews the evidence before response actions.” |
| 1:20–1:40 | Show Security Response; keep calls/messages unsent | “The location and contact are populated from saved details. The owner reviews any WhatsApp draft and sends it themselves. Server dispatch is labelled simulation unless a real provider is configured.” |
| 1:40–2:00 | Show history and a saved negative-control result | “Results persist privately in the account. We also test empty scenes and restart recovery. Accuracy and hosted-scale evaluation are still open work.” |

If analysis takes longer than the rehearsal budget, show an already completed result and identify it as a previous run. Never alter the progress indicator or invent latency to fit the pitch. An empty-scene run should complete with no incident; do not fabricate a threat for visual effect.

For a longer technical Q&A, demonstrate the required false-alarm reason and green three-second hold on an isolated disposable incident. Keep your own PIN private. Do not trigger a real call or notification during the presentation unless its test destination has been explicitly agreed in advance.

Fallback: retain a consented screen recording and the local server/model/fixtures. Explain whether you are showing the live app or a recording. Supabase sign-in and contact saving still need internet; local hosting is not offline authentication.

Answers to prepare: why these three classes; how false positives are handled; who reviews; what was prepared before the event; where private data lives; what the model/clip permissions are; what was measured versus mocked; and what would change for cloud scale.
